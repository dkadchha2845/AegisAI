# Persistence & auth. SQLAlchemy is pure-Python and needs no server for the
# default in-memory mode, so it does not require any setup to run the demo —
# it only enables durable storage when DATABASE_URL is configured. Auth (HS256
# tokens, and pbkdf2 password hashing when the line below is not installed)
# uses the standard library, no extra dep.
SQLAlchemy>=2.0

# Optional, and preferred when present: argon2id password hashing instead of
# pbkdf2-hmac-sha256. Argon2id is the memory-hard KDF and the one to use where
# it can be installed; pbkdf2 at 240 000 iterations is a sound standard KDF
# (NIST SP 800-132) and is what keeps the offline, clean-clone path working on a
# machine that cannot build a wheel. Both verify forever — the stored string
# says which wrote it — and a password checked against the older scheme is
# re-hashed with the newer one on the way through login, so installing this
# upgrades every account as its owner next signs in, with no migration and no
# password reset. /api/health reports which one is actually serving.
# argon2-cffi>=23.1

# Schema migrations for the evidence store (task 1.5). REQUIRED, not optional:
# a durable deployment has no other way to move an existing database forward,
# and `services/api/tests/test_migrations.py` runs every revision up and back on
# each test run — a clone that cannot import alembic cannot run the suite.
# The zero-setup ephemeral database still uses create_all and needs nothing here.
# >=1.16 for `path_separator` in alembic.ini; older releases fall back to
# splitting paths on spaces and colons.
alembic>=1.16

# Module 2 (FIGAE) fraud-intelligence graph. Pure-Python, no system libs, no
# server (the PDF named Neo4j; NetworkX runs in-process behind the same
# interface). REQUIRED, not optional: services.api.main imports the intel
# service at startup, so a clean install without this fails to boot — which is
# exactly what CI caught. The old <3.3 cap existed only to keep Python 3.9
# working; the floor is now 3.11, so the cap is gone.
networkx>=3.3

# Agent orchestration (task 1.3). See docs/adr/0004-langgraph-over-crewai.md.
# REQUIRED, not optional: services/api/orchestration/graph.py imports it at
# module level, and there is no fallback — a hand-rolled DAG would reimplement
# it badly (ADR-0004 rationale 5). Only the core graph primitives are used:
# StateGraph, the in-memory checkpointer, and draw_mermaid(). Upper bound
# because 0.x minor releases have moved the checkpointer's import path before.
#
# Cost, measured rather than assumed: +18 packages, including langchain-core.
# That is the ADR's stated consequence. The mitigation it names is enforced by
# the guard in ADR-0004 — no agent imports a LangChain LLM wrapper; all model
# access goes through our own LLMBackend.
langgraph>=0.6,<0.7

# Async job system (task 1.8). REQUIRED, not optional, and for the same reason
# alembic is: `services/api/jobs/` imports redis and `services/worker/` imports
# celery at module level, and a clone that cannot import them cannot run the
# suite — the queue tests would be skipped rather than failed, which task 1.7b
# is about. Both are pure Python and neither contacts anything at import time:
# with no Redis running, the API still boots, still answers, and runs the graph
# in-process, reporting `execution.mode: in-process` on /api/health.
#
# Cost, measured rather than assumed: +15 packages (amqp, billiard, click-*,
# kombu, prompt-toolkit, python-dateutil, redis, six, tzdata, tzlocal, vine,
# wcwidth). No compiled extensions, no system libraries.
celery[redis]>=5.4

# Test runner. Not optional in practice: the README asks you to run the
# verdict regressions before every push, and a fresh clone that cannot run
# them is a fresh clone whose checks get skipped.
pytest>=8.0

# Court-admissible evidence package as PDF (routes /api/session/{id}/report.pdf).
# Pure-Python, no system libs. The JSON package works without it; the PDF
# endpoint degrades to a clear 503 if it is absent.
reportlab>=4.0
